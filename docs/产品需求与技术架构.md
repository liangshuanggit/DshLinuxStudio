# 产品需求与技术架构

## 1. 产品目标

在普通安卓手机上提供一个可本地写代码、跑命令、安装 Linux 软件包，并能直接使用 DeepSeek Harness 的开发环境。核心约束是：**不依赖 root、不依赖 Termux、不需要电脑**。

## 2. 功能范围

### 第一功能：DeepSeek Harness

- 从零安装 Linux 根文件系统与 Node.js。
- 安装 `@deepseek-ai/dsh`。
- 填写 DeepSeek API Key。
- 启动 `dsh web` 并在 APP 内打开 Web UI。
- 工作目录固定映射到 Linux 中的 `/root/workspace`，避免 dsh 越权访问整个手机文件系统。

### 基础 Linux 环境

- `apt`、`bash`、`git`、`curl`、`python3`、`build-essential`。
- 自定义 `/etc/resolv.conf` 与 Ubuntu ports apt 源。
- 可运行任意 Shell 命令的终端页面。
- 可选 code-server，提供本地代码编辑能力。

## 3. 为什么选择 PRoot

Android 10+ 禁止应用从可写目录执行二进制（W^X）。解决方式是把 PRoot 及依赖重命名为 `lib*.so` 放进 APK 的 `jniLibs/arm64-v8a`，安装后由系统解压到 `nativeLibraryDir`，该目录具有可执行权限。PRoot 自身用 Bionic linker 链接，兼容 Android 内核。

Ubuntu rootfs 不随 APK 分发，而是在首次启动时下载并做 SHA256 校验，避免 APK 体积过大且便于升级。

## 4. 关键目录

| 宿主路径 | Guest 路径 | 用途 |
|---|---|---|
| `filesDir/mobile-linux/rootfs` | `/` | Ubuntu 根文件系统 |
| `filesDir/mobile-linux/workspace` | `/root/workspace` | 用户项目与 dsh 工作区 |
| `nativeLibraryDir/libproot.so` | — | PRoot 主程序 |
| `nativeLibraryDir/libprootloader.so` | — | PRoot loader |
| `rootfs/opt/node` | `/opt/node` | Node.js 运行时 |

## 5. 进程模型

`RuntimeService` 是前台服务，负责：

1. 执行安装任务并显示进度通知。
2. 启动并托管 `dsh web` 与 `code-server` 进程。
3. 收集 stdout/stderr 到 APP 日志面板。
4. 进程退出后刷新状态并停止服务。

API Key 不落盘到 rootfs；它从加密 SharedPreferences 读取，并作为 `DEEPSEEK_API_KEY` 环境变量传给 dsh 进程。

## 6. 安全边界

- WebView 只允许访问 `127.0.0.1` / `localhost`，避免任意外链在 APP 内打开。
- dsh 与 code-server 都只监听回环地址，不暴露到局域网。
- apt 源、Node.js、rootfs 全部使用 HTTPS + SHA256 校验。
- 用户项目目录只绑定 Linux 内的 `/root/workspace`，不绑定整块外部存储。
